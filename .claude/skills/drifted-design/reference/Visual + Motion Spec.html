04 — Performance & stack

Budgets, not intentions.

Budget

  • LCP under 2.5s on 4G with the hero object loaded — inbound and organic means Core Web Vitals are a ranking input, not a nicety.
  • Exactly one 3D object on the site. Under 2MB, lazy-initialised, static poster frame until interactive.
  • Grain is a ~1KB inline SVG data-URI, not a canvas noise function and not a PNG request.
  • Card video: poster + preload="none", fetched on hover intent.
  • Scroll-jacked sections release scroll below 768px. Pinned horizontal scroll on touch is a trap.
  • Every effect degrades to a static, well-composed layout under reduced motion — tested before launch, not after.

Stack

  • GSAP + ScrollTrigger — pinning, scroll-locking, stagger.
  • Lenis — smooth scroll.
  • Three.js — the single hero object, nothing else.
  • Everything else is CSS against the existing tokens. If an effect needs a library beyond these three, it isn't in the system yet.
  • Durations and easings are read from CSS custom properties, never hard-coded in JS — one place to change the feel of the whole site.
